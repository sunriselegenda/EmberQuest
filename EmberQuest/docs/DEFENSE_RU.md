# Материал для защиты Ember Quest

## План демонстрации на 3–4 минуты

1. Открыть главное меню и назвать тему: двумерная игра на Python и Pygame.
2. Запустить первый уровень. Показать красный ключ, открыть дверь и войти в портал.
3. На втором уровне подойти к синему ключу в красном цвете: ключ не подберётся. Нажать пробел, подобрать ключ и открыть синюю дверь.
4. Показать паузу Esc, меню уровней и сохранённые звёзды.
5. На позднем уровне показать шипы, стражей и возрождение. Для их открытия нужно сначала пройти предыдущие уровни.
6. Показать `model.py`, затем `game.py`: правила отделены от отрисовки.
7. Запустить автотесты и показать результат.

Не удаляй сохранение перед защитой, если хочешь показать уже открытые поздние уровни. Для демонстрации новой игры можно временно использовать другую папку сохранений.

## Короткое выступление

Тема моего проекта — разработка двумерной игры Ember Quest на языке Python с использованием библиотеки Pygame. Это приключенческая головоломка с видом сверху. Герой должен пройти древний храм, собирая ключи и открывая двери разных цветов.

Основная механика построена на переключении цвета персонажа клавишей пробела. В игре три цвета: красный, синий и зелёный. Ключ подбирается только при совпадении цветов. Чтобы открыть дверь, требуется не только нужный ключ, но и соответствующий цвет героя. После открытия один ключ расходуется.

В проекте реализованы шесть уровней с постепенным усложнением. Вначале игрок знакомится с управлением, затем появляются другие цвета, препятствия и движущиеся стражи. Дополнительно можно собирать кристаллы и получать звёзды за более полное прохождение.

Архитектура разделена на несколько частей. Модель отвечает за состояние карты и правила взаимодействия. Игровой класс обрабатывает события, рисует объекты и воспроизводит звук. Отдельный компонент сохраняет прогресс в JSON. Такое разделение упрощает проверку и изменение проекта.

Движение логически выполняется по клеткам, но отображается плавно с помощью интерполяции. Графика и звуки включены в проект вместе с генераторами. Игра имеет главное меню, выбор уровня, паузу, правила и экран результатов.

Для проверки подготовлены автоматические тесты механики, сохранений и интерфейса. Также проверено существование безопасных маршрутов через все уровни со сбором всех кристаллов. Проект можно развивать, добавляя новые карты, переключатели и редактор уровней.

## Возможные вопросы преподавателя

**Почему выбран Pygame?**
Он предоставляет работу с окном, изображениями, событиями и звуком, но оставляет реализацию игровых правил в коде Python. На таком проекте можно показать программирование, а не только настройку готового движка.

**Где используется ООП?**
`World` представляет состояние уровня и операции над ним. `Game` объединяет игровой цикл и визуальное представление. `Progress` отвечает за сохранения. `MoveResult` — структура результата взаимодействия. Наследование здесь не потребовалось; применяется композиция.

**Где проверяются столкновения?**
В `World.move()`: до изменения координаты проверяется целевая клетка. Стена блокирует шаг, дверь проверяет ключ и цвет. Столкновение с движущимся стражем рассчитывается отдельно по расстоянию между его центром и героем.

**Почему нельзя пройти через закрытую дверь другого цвета?**
Условие открытия включает две независимые проверки: совпадение цвета и наличие ключа. Если хотя бы одна не выполнена, координаты героя не меняются.

**Почему движение плавное, если игра клеточная?**
Логические координаты целочисленные, а координаты изображения вычисляются между старой и новой клеткой за 0,12 секунды. Это линейная интерполяция.

**Для чего нужен dt?**
Это время между кадрами. Умножение скорости на dt позволяет обновлять движение и анимацию по времени, а не по количеству кадров.

**Как работает переключение цвета?**
Цвета находятся в последовательности из трёх элементов. Индекс увеличивается на один и берётся по модулю три. После третьего цвета снова получается первый.

**Какие структуры данных используются?**
Список строк для карты, словари для ключей и дверей, множества для кристаллов и шипов, Counter для числа ключей. Координаты — кортежи.

**Как сохраняется прогресс?**
В JSON в папке пользователя. Запись выполняется через временный файл с последующей заменой. Повреждённое сохранение не должно приводить к аварийному завершению.

**Как проверяли проходимость?**
Поиск в ширину строит пути по доступным клеткам. Тест проходит карты, подбирает ключи, открывает двери, собирает все кристаллы и доходит до выхода. Клетки шипов и линии патрулей исключены.

**Что происходит при гибели?**
Текущий уровень создаётся заново из исходной карты. Счётчик возрождений увеличивается, секундомер продолжает текущую попытку. Пройденные уровни не закрываются.

**Что можно улучшить?**
Добавить редактор, больше вариантов карт, переназначение управления и сохранение внутри уровня. Сейчас эти возможности не реализованы.

## Что изучить в коде перед защитой

1. `World.__init__()` — как символы карты превращаются в объекты.
2. `World.move()` — полный порядок проверок движения.
3. `World.switch()` и `collect_here()` — цвет и подбор ключа.
4. `Game.event()` — реакции на клавиши.
5. `Game.update()` — обновление по dt.
6. `Game.draw_world()` — порядок отрисовки.
7. `Progress.complete()` — лучшие звёзды и открытие уровней.
8. `path_to()` в тестах — пример поиска в ширину.
